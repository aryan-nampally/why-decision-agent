# ADR-009: Infrastructure as code with Terraform

## Context

Roughly half of Keelwright's AWS resources were created by hand in the console. Two incidents last quarter were caused by configuration drift between staging and production. The platform team wants every environment reproducible from version control.

The team already knows HCL from a previous employer, and AWS is our only cloud provider today.

## Considered Options

1. **Terraform** with remote state in S3 and DynamoDB locking
2. **AWS CloudFormation / CDK**
3. **Pulumi** (TypeScript)

## Decision Outcome

Chosen option: **Terraform**, one state per environment per service, modules in a shared `infra-modules` repository.

CDK was a close second but ties us more tightly to AWS. Pulumi was rejected because the backend team works in Python and Go, not TypeScript.

## Consequences

- Good: drift is visible in plan output; environments are reproducible.
- Bad: state files are a new operational risk; we will enforce locking and versioned buckets.
