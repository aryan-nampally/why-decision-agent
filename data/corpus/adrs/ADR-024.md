# ADR-024: Monorepo for web frontends

## Context

The shipper portal, the staff console and the marketing site live in three repositories with three copies of the design system. Shared components drift within weeks of every release.

## Considered Options

1. **pnpm workspaces + Turborepo** in a single frontend monorepo
2. **Publish the design system as a versioned npm package**

## Decision Outcome

Chosen option: **pnpm workspaces with Turborepo.** A versioned package was rejected because upgrades would still lag in each app.

## Consequences

- Good: one pull request can change a component and every consumer.
- Bad: CI must use remote caching to stay fast.
